# Remove the 1.x API

<a id="adr-0020"></a>

- **Decision.** The 1.x root module `json/blueprint` and its schema module `json/blueprint/schema` are removed, with the internal Dynamic decoder and the FFI only they used. Generated modules lose `decode_<name>_json_native`. Every text decoder the package offers now parses through the strict parser, so the default byte and depth bounds of [ADR-0019](0019-bound-nesting-depth-by-default.md#adr-0019) apply to all of them.
- **Supersedes.** [ADR-0007](0007-freeze-legacy-source-and-wire-contracts.md#adr-0007), which kept the 1.x surface frozen and available. The owner ruled on 2026-11-25 that version 3.0 removes it, with a migration note in place of a compatibility path.
- **Problem.** `blueprint.decode` and the generated `decode_<name>_json_native` parsed with `gleam/json` behind a 1 MiB byte check only. They admitted documents nested deeper than the default depth bound, repeated keys and inexact numbers that the strict parser refuses. A second parser beside the bounded one is a path around the limits, and a caller cannot tell from the function name which guarantees apply.
- **Alternatives.** Adding a depth check to the 1.x path keeps two parsers and two sets of guarantees. Keeping the 1.x API frozen keeps the bypass. Routing 1.x decoding through `value.parse` changes its acceptance and error type anyway, so it would no longer be the frozen API.
- **Consequences.** This is a breaking change for 1.x callers and for callers of the generated native decoder. Codecs replace the record, list, optional, union, enum and tuple combinators; their wire formats differ as the migration guide lists. Recursive types have no codec form: an application parses with `value.parse` and walks the `Value` with its own function, and no schema is derived for it. Legacy-envelope data (`{"type", "data"}` unions, `{"enum": label}` enums) needs an application reader or a data migration. The `gleam/json` bridges `codec.decoder` and `value.decoder` remain: they parse nothing, and the caller that parses owns the limits. Generated modules no longer import `gleam/dynamic`, so a mapping whose output type comes from that module names one of its functions as a reference.
- **Evidence.** The [migration example](../../examples/test/migration_test.gleam) moves a 1.x record to a codec, shows each wire difference and reads recursive data from a bounded `Value`, refusing one nested beyond the default depth. The compiled codec tests check that generated source contains no `gleam/json` parsing and that a generated decoder refuses input nested beyond 128 levels.

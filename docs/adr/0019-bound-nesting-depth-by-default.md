# Bound nesting depth by default

<a id="adr-0019"></a>

- **Decision.** Strict text admission has two bounds, and both are on by default: at most 1 MiB of input (1,048,576 bytes) and at most 128 levels of nesting. `value.with_max_bytes` and `value.with_max_depth` change either bound. `value.unlimited()` removes both, and a trusted caller chooses it explicitly. A document nested deeper fails with `DepthLimitExceeded`. There is no value-count bound.
- **Supersedes.** The byte-only default of [ADR-0014](0014-adopt-native-erlang-decoding-with-byte-admission.md#adr-0014). Its native parsing, duplicate detection and exact numbers stand. The owner ruled on 2026-11-25 that the bounds are on by default, that only bytes and depth are kept, and that trusted callers opt out explicitly.
- **Problem.** A byte bound does not bound nesting. A 1 MiB document can nest about 500,000 levels. Every function that walks a parsed value recurses once per level, so a consumer had to check depth itself before calling any of them. On JavaScript a deep document exhausts the host stack inside those functions, where the failure is thrown and not returned. On Erlang a deep value makes rendering and every recursive consumer slow.
- **Why 128.** It is the recursion limit `serde_json` applies by default, the reference this package is compared with. Ordinary data, schemas generated by Pydantic and Zod, and tool arguments nest far less than 128 levels. The tests parse, convert and decode 128 levels on Node and on Erlang.
- **Why no value-count bound.** Every value takes at least one byte of text, so the byte bound already bounds the number of values. A separate count added work to every array item and member for no further guarantee.
- **Mechanism.** The byte check is one comparison before parsing. On Erlang the OTP decoder threads an accumulator through its container callbacks. Each container's accumulator keeps the two elements it had before, and the slot that held the refusal marker holds the container's depth while it is admitted. The only added work is one comparison when a container opens. On JavaScript the scan that already checks duplicate names after `JSON.parse` counts depth in the same pass. When the reviver exhausts the stack first, a depth scan decides between `DepthLimitExceeded` and `RuntimeCapacityExceeded`.
- **Consequences.** This is a breaking change: a document nested deeper than 128 levels that 2.x admitted is now refused unless the caller raises or removes the bound. `ParseReason` gains `DepthLimitExceeded`, and `is_limit_exceeded` is true for it. A malformed document reports its syntax error on both targets, because grammar is checked before depth. On Erlang a refused document is still parsed to its end, but nothing below the refused container is retained. The frozen 1.x root API and generated codecs parse with `gleam/json` and keep their byte bound only; a generated codec's fixed shape bounds the depth it walks.
- **Cost.** The [dated observations](../BENCHMARKS.md#default-depth-bound-2026-11-25) compare the parent commit with this change. On Erlang a document made only of nested arrays parsed about a tenth slower, against two thirds slower for the earlier opt-in design that also counted values. Records and flat arrays did not parse slower. On Node the rows overlap.

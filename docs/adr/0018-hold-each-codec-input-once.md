# Hold each codec input once

<a id="adr-0018"></a>

- **Decision.** Every combinator stores one closure, a thunk that captures the combinator's inputs once (child codecs, the record continuation and getter, enum variants, bounds, caller callbacks) and builds the codec's operations each time they are needed. A union variant keeps its tag, an identity and one such thunk for its payload operations. A tagging function, or a unit variant's tagged value, holds only that identity: an Erlang reference or a JavaScript symbol, minted when `variant` or `unit_variant` runs. The tagged value carries its payload untyped until the union encodes it, finds its variant by identity and so knows the payload's type.
- **Problem.** A BEAM process copy does not preserve sharing. Up to 2.1.1 a codec was a record of closures, and each combinator stored several closures over the same inputs: a record field held its continuation in twelve references and a string enum its labels in five. A copied codec cost many times its in-heap size (an application's agent 289 kB flat against 19 kB in-heap; a run-time enum label about 1 kB), and in 2.0 and 2.1.0 the cost multiplied per nesting layer until a consumer VM ran out of memory. The [codec practice guide](../CODEC-PRACTICE.md) could not remove a codec captured by a later field, and its run-time enum rule rebuilt and re-validated the enum on every conversion.
- **Promise.** From 2.2.0, on Erlang, a codec's flat size equals its in-heap size apart from sharing inside the caller's own values, one reference per union variant held by the variant and by its tagging function or tagged value, module literals (a process copy does not copy them, though `erts_debug:flat_size` counts each reference), and a codec with a definition mistake: the library adds no other duplication, a value captured by a continuation is copied once, and a run-time label costs its own data once. Later 2.x releases keep the promise; copy-size tests check every public function of the package that returns a codec, and a completeness check fails when one has none.
- **Rules that follow.** Derived data that grows with the inputs, such as an enum's label list, may replace them but is never kept beside them; it is derived inside the operation that needs it, so a codec keeps no cache. Fixed-size derived data, such as integer bounds, digit counts and a definition mistake, is computed once when a combinator is built and shares no subterm with an input. Operations are rebuilt per use and per element, except for input-free leaves, whose operations are module constants; conversion allocates 0.87–0.91 times the words 2.1.1 did on records, 0.98 times for the schema, and 1.08–1.18 times on union-heavy data.
- **Behavior.** Results, errors, paths, schemas, placeholders, definition errors and the order and number of caller callbacks are as in 2.1.1, held by the repository's codec probe, except in two union cases. A value tagged by a tagging function or tagged value from another `codec.union` block panics when encoded, naming the encoding union's tags; 2.1.1 encoded it with the other union's payload codec. A union payload is encoded when the union encodes a value, for the value `match` returned only: a tagging function called in `match`, or anywhere else in the union block, no longer encodes its payload when it is called. So a `match` that calls several tagging functions sees payload encode callbacks later or not at all, and a tagged value made once in the union block encodes its payload, and finds any definition mistake in it, on every encode instead of while the union is built; `check` now reports such a mistake. A scan of Fabric, decisions, relay, llm_wire and the consumer applications found neither. Outside the 2.x contract, separately built codecs containing a union are no longer equal, input-free leaves such as `codec.string()` are now equal on JavaScript too, building a union is no longer pure, and stack frames naming library functions change.
- **Amends.** [ADR-0004](0004-continuation-records-and-definition-errors.md#adr-0004) keeps its continuation API, placeholder-driven schema discovery and panic at first use, with one exception to its `check` guarantee: a tagging function or tagged value used in another union's `match` is a source mistake that `check` cannot see, because it lies in which value `match` returns. It panics when such a value is encoded.
- **Rationale.** One stored closure per input gives the copy promise while keeping each combinator's operations together and typed, as in 2.1.1, so the compiler still checks the internals; only the union payload passes through one coercion, guarded by the variant's identity. A tagging function that held its payload codec would hold every payload twice, so nested unions would copy at 2^depth. References and symbols are unique across nodes and restarts and need no mutable module state.
- **Alternatives.** Against this representation, an untyped data tree (one node per combinator and an interpreter per operation) copied the same, ran 1.1–2.0 times faster and allocated 20–70% less, but its interpreters escape the compiler and spread each record's behavior over about thirteen functions; it stays the fallback if more speed is needed. A typed closure dispatching on an operation sum type was slower than both. Building a union on each use removed both union exceptions but ran 1.7–1.9 times slower and allocated 3.6–4.4 times more on union-heavy conversion. Integer identities copied smaller, but are unique only within one runtime, so a codec carried to another node could collide with a local variant and break the coercion's guard; on JavaScript they needed a mutable counter. Keeping several closures per combinator with smaller captures (2.1.1, or passing the field record to field operations) still copies each input once per holder. Generation by default cannot express run-time enums or unions. A `persistent_term` registry or run-time compiled codec modules need global GC or code purges and have no JavaScript form.
- **Consequences.** A minor release, 2.2.0; public signatures are unchanged. Consumers whose minimum version is below 2.2.0 keep the guide's copy rules; with a minimum of 2.2.0 they are no longer needed. The pending rulings on record continuations and on schema-generated children close: a child codec bound before a field chain is held once like any other input. Release notes carry the two union cases and the panic text.
- **Evidence.** The implementation passes the gate on both targets, the codec probe byte-identical to 2.1.1 on both targets apart from the two union cases, and byte-identical consumer payloads and schemas from a consumer application and decisions. Copies of consumer values fell 8.8–85 times (an application's agent 289 kB to 33 kB flat), and the library's own `contract.value_codec` and generated runtime codecs hold their inputs once through an internal deferred constructor; conversion time ratios against 2.1.1 were 0.87–1.06 on consumer shapes, 0.56–1.03 on the Erlang fixture (one generated-schema row at 1.17 does not reproduce in isolation) and 0.16–1.05 on Node. Three benchmark rows of `codegen.runtime` codecs, which the deferred constructor rebuilds on every use, are 1.16–1.22 on one target. Of six behavior-preserving speed slices, five were kept and a direct text encoder was dropped for being slower. The [dated observations](../BENCHMARKS.md#codec-inputs-held-once-2026-11-20) give the method and every row.

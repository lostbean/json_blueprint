# Bind record fields by name and separate definition mistakes from input

<a id="adr-0004"></a>

- **Decision.** The ordinary record path uses `field`, `optional_field`, and `success` continuations with getters last under `get:`. Source definition mistakes panic at the first affected use; `check` returns typed `DefinitionError` for runtime definitions.
- **Rationale.** Arity-specific builders and nested product tuples burden larger caller records. Continuations retain named decoded bindings and permit a later field's check to depend on earlier values. Getter argument order lets the continuation establish the record type before record access is checked.
- **Alternatives.** Arity families stop at a selected width. Product-tuple assembly exposes grouping in both directions. Pipe builders bind same-typed fields by constructor position and cannot express the same dependent field checks. Deferred typed value errors could make a source mistake appear retryable; constructor `Result` encouraged assertions with generic failures.
- **Consequences.** Placeholder-driven discovery requires schema shape independent of placeholder data. Lazy source definitions may fail late, so callers check runtime-built definitions at startup. No memoized discovery or universal linear-time guarantee is inferred from the public builder.
- **Evidence.** [API redesign](https://github.com/lostbean/json_blueprint/commit/94438b93b638a2ecf2e4443bd9c2c3cbf97b7713) and [getters last](https://github.com/lostbean/json_blueprint/commit/bb4da39c29054c0086124052076c7a2c79afa4ff) are dated 2026-10-02. Oversight release decision D4 contains the panic/typed-runtime alternatives; the release report's original deferred-error proposal is superseded by implementation. The former README builder comparison measured three record shapes; its results are evidence for selection, not an independent performance promise. [codec.gleam](../../src/json/blueprint/codec.gleam) and [public API tests](../../test/api_control_test.gleam) own current behavior.

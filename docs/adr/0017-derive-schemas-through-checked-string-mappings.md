# Derive schemas through checked string mappings

<a id="adr-0017"></a>

- **Decision.** `codec.map_enum_labels` returns a schema with every string-enum label passed through a caller function, and `codec.map_descriptions` does the same for every description. They are the only public operations that derive a `Schema` from another. Neither changes structure, and neither touches the codec the schema came from.
- **Scope of strings.** A label is the only string in the finite profile that a caller supplies as data and that a document carries as a value. Property names and union tags are also in documents, but they are the shape of a caller's types: mapping them changes which objects are accepted and can collide in ways one function over strings cannot report well, so they stay fixed. Descriptions are annotations, not acceptance, and mapping them cannot fail; folding them into the label function would make an infallible change fallible and would rewrite prose with a function written for identifiers. The profile has no formats, patterns, titles or free string constants.
- **Rationale.** A consumer that records exchanges replaces identifiers that differ between runs before it stores a request. Labels and descriptions built from runtime data carry such identifiers into a schema, and an opaque schema could be read but not republished with other strings. The internal tree accessors would have given that consumer a way to build unchecked structure.
- **Invariant.** The mapped tree passes the same definition check as a loaded document before it becomes a `Schema`, so `contract.from_schema` stays total. Mapping keeps the number of labels, so an enumeration cannot become empty; the empty string is a valid label; two labels of one enumeration mapped to one string return the existing `DuplicateEnumLabel` with the repeated mapped label. No error variant is added.
- **Alternatives.** A public schema constructor or a general tree rewrite exposes the model that [ADR-0005](0005-opaque-schema-and-stable-projection.md#adr-0005) keeps opaque. One function over every string in a schema has no honest name and renames properties. Deduplicating colliding labels silently changes what the schema accepts. Mapping the codec instead of the schema would need the inverse function to decode.
- **Consequences.** The additions are source-compatible with 2.0.0 and need a minor release to publish. A schema with mapped labels describes mapped documents: the source codec still reads and writes its own labels and `contract.decode` reports `ContractMismatch` for it, so a caller maps documents with the same function. A schema kind added later must state whether it holds labels.
- **Evidence.** [The mapping tests](../../test/schema_label_mapping_test.gleam) compare mapped schemas with the schemas of codecs built from the mapped strings, across records, optional fields, lists, nullable values, pairs and unions, and cover the collision. [The schema-inspection example](../../examples/src/examples/schema_inspection.gleam) shows a caller.
